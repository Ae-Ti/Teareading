## 프로필 공개 범위 (결정)

**프로필은 비공개가 기본이고 친구에게는 보인다.** 인스타그램의 비공개 계정과 게시물처럼 동작한다.

- [ ] `profiles.is_public` 기본값을 `false`로 바꾼다
- [ ] `profile_visible`에 친구 조건을 넣는다: 본인, 공개 프로필, 또는 친구. 차단 관계면 제외
- [ ] `/u/[id]`의 `hidden`이 `is_public`만 보고 있다. `profile_visible`과 같은 기준으로 바꾼다
- [ ] 글별 `is_public`은 그대로 둔다. 공개로 지정한 글만 볼 수 있는 사람(공개 프로필 방문자·친구)에게 보인다
- [ ] 비공개 프로필의 소개(`bio`)를 표에서 직접 읽지 못하게 한다. 컬럼 권한을 나누고 `profile_visible`을 확인하는 함수로 내보낸다
- [ ] 개인 설정의 공개 전환을 눈에 띄게 안내한다
- [ ] 개인정보처리방침 수정: 비공개가 기본, 친구에게 공개되는 범위, 참여 모임은 모임 화면에서 보임, 공개한 독서록의 책 제목은 보임
- [ ] 상단 메뉴에 `가이드` 링크를 되살린다 (대시보드의 핫게시물은 유지)

## 고쳐야 할 문제

- [ ] **차단 후 친구 유지**: 차단해도 친구로 남아, 차단당한 사람에게 접속 여부와 오늘의 독서·다도 시간이 보이고 공개 친구 목록에도 남는다. `blocks` insert 트리거로 양쪽 친구 관계와 대기 중인 `live_requests`를 지운다. 해제해도 친구는 복구하지 않는다
- [ ] **차단 사실 노출**: 차단당한 사람이 요청하면 "차단 관계에서는 요청을 보낼 수 없어요."가 나온다. 차단당한 쪽에는 "지금은 요청을 보낼 수 없어요"만 보여 주고, 차단 문구는 차단한 본인에게만 쓴다
- [ ] **요청 반복**: 거절돼도 곧바로 다시 요청할 수 있다 (6번 거절, 6번 생성). 같은 사람에게 같은 종류의 요청은 거절 후 24시간 막는다
- [ ] **큰 사진 업로드**: 앱은 5MB까지 허용하지만 Vercel 함수의 요청 크기 제한은 4.5MB로 알고 있다 (프로덕션에서는 시험하지 못함). 브라우저에서 긴 변 1600px로 줄여 보내고 서버 재인코딩은 유지한다
- [ ] **`test:profile:db` 실패**: 공개 필드 기대값에 `is_public`이 없다

## 작은 것

## 태일이 처리

- 내 방 친구 공개: `20261111000100_friend_room.sql`, `/space/room/[id]`, 친구의 공개 프로필에 `방 구경하기`. `/u/[id]`와 개인정보처리방침에 한 줄씩 넣었다
