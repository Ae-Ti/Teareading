## 3. RLS 점검

`npm run test:rls` (`tests/rls.db.test.ts`) — **9개 통과**. 두 계정(A, B)과 비로그인으로 시도했다.

- 비로그인: 모든 테이블·뷰 조회 불가, `start_timer`·`is_group_member` 호출 불가
- 타이머: B가 A의 세션 조회·종료 불가, 본인도 직접 insert/update로 완료 위조 불가(RPC만 가능), 남의 출석 조회 불가
- 독서기록·차 칼럼: 남의 글 조회·수정·삭제·대리 작성 불가, 자기 글 주인을 남으로 바꾸기 불가
- 모임: 남을 모임장으로 생성, 비모임장 수정·삭제, 모임장 넘기기, 모임장 역할로 가입, 남을 강제 가입, 멤버의 역할 승격, 멤버가 모임장 내보내기, 모임장 본인 탈퇴 모두 불가. 모임장의 내보내기는 허용
- 찻집 체류 기록: 남의 기록 조회·수정·대리 작성 불가
- 프로필: 남의 닉네임 변경, 프로필 삭제 불가
- Realtime: DB 테이블을 publication에 올리지 않았다. 찻집은 Presence만 쓴다
- **채팅·DM은 테이블이 생기면 이 파일에 같은 방식으로 추가한다.** 단체 채팅은 `is_group_member()`로 조회·작성을 막고, 탈퇴 후 접근이 막히는지 확인한다

웅싯 E2E(`board.spec`, `community.spec`)가 다루지 않은 경계 상황을 계정 3개(1440 2개, 360 터치 1개)로 확인했다.

| 항목 | 결과 |
|---|---|
| 비로그인 | `/board`는 로그인으로 이동, `posts`·`post_comments`·`post_likes`·`post_views`·`group_mutes` REST 조회 차단 |
| 스크립트 삽입 | 글·댓글의 HTML은 글자로만 표시 |
| 긴 제목·본문·댓글, 게시판 목록 | 360·1440 페이지 가로 넘침 없음 |
| 모바일 하단 탭 6칸 (360) | 칸 56px, 글자 잘림 없음 |
| 검색 특수문자, 잘못된 `page`·`category`·`sort`·`field`, 잘못된 글 주소 | 오류 없이 처리 |
| 조회수·추천 | 새로고침으로 조회수가 늘지 않음, 추천 연타 후 값 정상 |
| 글 등록 연타 | 1건만 저장 |
| 남의 글·댓글 | 수정·삭제 버튼 없음 |
| 멤버 관리 팝업 | 포커스가 팝업 안에 있음, 360에서 화면 안에 들어옴 |
| 채팅을 연 채 차단·퇴장 | 전송이 거부되고 이유가 표시되며 저장되지 않음. 퇴장자에게 새 메시지가 오지 않음 |
| 메시지 삭제 | 터치 기기에서 삭제 버튼 보임, 메시지 탭 미리보기에 지운 내용 없음 |
| 퇴장 후 메시지 탭 | 해당 모임이 목록에서 사라짐 |

### 발견한 문제 (담당: 웅싯)

4. **강제 퇴장한 사람이 바로 다시 가입할 수 있다.** 퇴장 직후 모임 화면에 `모임 가입`이 그대로 보이고, 누르면 다시 멤버가 되어 채팅방에 들어간다. `group_members` 가입 정책이 본인 가입을 모두 허용하기 때문이다. 메시지 차단은 재가입해도 유지되지만 강제 퇴장은 기록이 남지 않는다. 막으려면 퇴장 기록 테이블과 가입 정책 변경이 필요하다.
5. **마지막 페이지 뒤 주소를 열면 목록 오류 화면이 나온다.** `/board?page=999`처럼 글 수를 넘는 페이지에서 PostgREST가 416(`PGRST103`)을 돌려주고, `lib/board.ts`의 `listPosts`가 이를 오류로 처리한다. 마지막 페이지의 유일한 글이 지워진 뒤 그 주소로 돌아와도 같다. 빈 목록으로 보여 주거나 마지막 페이지로 보내면 된다.
6. **전각 공백(`U+3000`)만 넣은 글이 등록된다.** `validatePost`와 DB 제약이 ASCII 공백만 제거한다. 영향은 작다.

참고: 채팅을 열어 둔 채 메시지 차단을 당하면 입력창은 새로고침할 때까지 잠기지 않는다. 전송은 거부되고 이유가 표시되므로 결함으로 보지 않았다. 단체 채팅의 하이드레이션 오류는 9장 2번과 같은 문제이고, 게시판·모임·메시지 목록 화면에서는 나지 않았다.
