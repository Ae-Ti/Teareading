# 개인 메시지(DM)·차단 작업 명세

- 담당: 웅싯 / 일정: D5 / 우선순위: DM P0, 차단 P1
- 작업 브랜치: `feat/woong-dm`
- 대상: `/u/[id]`의 메시지 진입, `/dm`, `/dm/[threadId]`, `dm_threads`, `dm_messages`, `blocks`
- 기준: 기능명세 6.3, 1주 개발 계획 2장·3.3·4.1·6.4

## 이용자 흐름

로그인 이용자가 상대의 공개 프로필에서 `메시지 보내기`를 누르면 기존 1:1 대화로 이동하거나 새 대화를 만든다. `/dm`에는 상대 아바타·닉네임·마지막 메시지·시간이 보인다. 대화 화면에서 메시지를 보내고 실시간으로 받으며, 실패 시 같은 메시지를 재시도한다. 차단 기능이 포함된 경우 차단한 상대와의 대화 생성·전송은 거부하고 이유를 안내한다.

## 구현 작업

- [x] `dm_threads`에 정렬된 `user_a < user_b` 쌍과 unique 제약을 둔다. 같은 상대에게 동시에 시작 요청이 와도 대화방은 1개만 만들어지게 한다. 자기 자신과 대화 시작은 막는다.
- [x] `dm_messages`에 `thread_id`, `sender_id`, `body`, `client_id` unique, `created_at`을 저장한다. 참여자만 조회·작성할 수 있게 RLS를 구성하고 작성자 위조·빈 본문을 차단한다.
- [x] `/dm` 목록은 본인이 참여한 대화만 조회하고 마지막 메시지·시간을 정확히 표시한다. 빈 목록, 로딩, 조회 실패 상태를 제공한다.
- [x] `/dm/[threadId]`는 상대 식별 정보, 메시지 목록과 입력 영역을 제공한다. 모임 채팅의 메시지 UI·전송 상태·페이지네이션을 재사용하되 대화별 구독을 분리한다.
- [x] `client_id`는 최초 전송 시 만들고 실패 재시도에 재사용한다. Realtime 수신과 낙관적 메시지를 중복 표시하지 않는다. 이탈 시 구독을 해제한다.
- [x] `dm_started`, `dm_message_sent`는 대화 생성·메시지 저장 성공에 맞춰 기록한다. 기존 대화 재진입을 신규 생성으로 중복 집계하지 않는다.
- [x] P1 `blocks`는 `blocker_id`, `blocked_id`로 만들고 본인만 차단·해제할 수 있게 한다. 어느 한쪽이 상대를 차단하면 새 대화 생성과 메시지 전송을 DB 정책에서도 막는다. 차단 시 기존 대화 조회 범위와 UI 처리는 정책을 명시하고 태일과 확인한다.

## 완료·검수 기준

1. A가 B 프로필에서 두 번 시작해도 대화방 1개로 이동한다. 서로 동시에 시작해도 같다.
2. 양쪽 계정에서 메시지가 실시간으로 나타나고 새로고침 후 유지된다. 실패·재시도·중복 클릭 뒤 DB에는 `client_id`당 1건만 남는다.
3. 제3자는 대화 URL 직접 접근, 조회, 전송이 불가능하다. 본인에게 메시지를 보낼 수 없다.
4. 차단 기능이 포함되면 차단·해제와 양방향 생성·전송 거부를 다른 계정으로 확인한다. 거부 이유가 화면에 보인다.
5. 360px/1440px에서 목록·대화를 조작하고 이벤트, `npm run lint`, `npm run typecheck`, `npm run build`를 확인한다.

## 의존성·PR 경계

공개 프로필의 진입점과 모임 채팅의 공통 메시지 컴포넌트를 재사용한다. `blocks`는 일정상 P1이며, DM P0 구현을 지연시키지 않도록 별도 작은 PR로 분리할 수 있다. 마이그레이션·RLS는 새 파일로 추가하고 타입을 재생성하며 태일 확인 후 머지한다. 신고·알림·외부 메신저는 범위에 없다.
