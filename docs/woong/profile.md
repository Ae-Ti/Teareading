# 마이페이지·프로필 작업 명세

- 담당: 웅싯 / 일정: D3 / 우선순위: P0
- 작업 브랜치: `feat/woong-profile`
- 대상: `/mypage`, `/mypage/edit`, `/u/[id]`
- 기준: 기능명세 1.2, 1주 개발 계획 3.2·3.3·4.1·6.4

## 이용자 흐름

로그인 이용자는 마이페이지에서 계정 이메일과 프로필 정보를 확인하고 닉네임·한 줄 소개·아바타를 수정한다. 다른 이용자의 공개 프로필에는 닉네임, 아바타, 소개, 가입일, 참여 모임만 표시한다. 개인 독서기록과 차 칼럼 원문은 공개 프로필 조회·응답·화면에서 제외한다.

## 구현 작업

- [x] `/mypage`에 본인 프로필, 수정 진입, 로그아웃 진입을 제공한다. `/me`는 태일 담당 기록장이므로 링크와 라벨만 연결한다.
- [x] `/mypage/edit`에서 닉네임 2~20자·중복 여부, 소개 길이, 이미지 형식과 2MB 용량을 검증한다. 저장 중 중복 제출을 막고 필드별 오류·성공 상태를 보여준다.
- [x] 아바타는 Supabase Storage의 `avatars/{user_id}/...` 경로에 저장한다. 버킷 정책으로 본인 경로만 쓰게 하고 파일 이름·형식 검증을 서버/스토리지 정책에서도 확인한다. 기존 이미지 교체 실패 시 프로필이 깨지지 않게 한다.
- [x] `profiles`의 본인 행만 업데이트하고 저장 후 새로고침·다른 기기에서도 같은 값을 확인한다. 성공 시 `profile_updated` 이벤트를 기록한다.
- [x] `/u/[id]`는 공개 필드만 선택해 조회한다. 존재하지 않는 ID는 조회 불가 상태를 보여준다. 모임 목록 링크는 태일의 `groups`·`group_members` 데이터와 연결한다.
- [x] 공개 프로필의 `메시지 보내기` 진입점은 DM 기능 브랜치에서 완성한다. 해당 PR이 머지되기 전에는 동작하지 않는 링크를 노출하지 않거나 명확한 상태를 제공한다.

## 완료·검수 기준

1. 본인 계정은 닉네임·소개·아바타를 저장하고 새로고침 뒤에도 확인한다. 다른 계정은 본인 프로필을 수정할 수 없다.
2. 중복 닉네임, 빈 필수값, 2MB 초과 파일, 이미지 외 파일, 업로드·저장 실패를 확인한다. 실패 시 기존 프로필 정보가 유지된다.
3. 다른 계정으로 공개 프로필을 열어 공개 항목만 보이는지 확인한다. 네트워크 응답과 데이터 조회에도 개인 기록·칼럼 원문이 포함되지 않는다.
4. 존재하지 않는 사용자 ID와 비로그인 접근에 알맞은 상태가 표시된다. 360px/1440px에서 읽고 수정할 수 있다.
5. `profile_updated` 이벤트, `npm run lint`, `npm run typecheck`, `npm run build`를 확인한다.

## 의존성·PR 경계

첫 마이그레이션의 `profiles`와 태일의 모임 멤버 스키마를 사용한다. Storage 버킷·정책 또는 RLS 변경이 필요하면 새 마이그레이션으로 추가하고 타입 재생성 후 태일 확인을 받는다. 프로필 공개 범위 변경은 독서기록·차 칼럼의 비공개 정책과 함께 검토한다.

## 구현 기록

로컬 구현·검증과 공유 파일 변경사항은 [프로필 작업 기록](./profile-progress.md)을 참고한다. 위 체크는 구현 상태이며, 원격 환경 적용·프리뷰·상대 리뷰는 별도다.
