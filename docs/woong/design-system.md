# 디자인 시스템·전역 내비게이션 작업 명세

- 담당: 웅싯 / 일정: D1~D2, D3 추가 시안 / 우선순위: P0 기반
- 작업 브랜치: `feat/woong-design-system`
- 기준: 1주 개발 계획 4.1, 3.2, 5.3 및 기능명세 7.1

## 목표와 범위

다도·독서 서비스의 시각 언어를 정의하고 모든 담당 화면이 같은 토큰과 공통 컴포넌트를 쓰도록 한다. D1에는 무드보드 2안, 선택한 방향, 대시보드·타이머·로그인·가입 와이어프레임을 정리한다. D2에는 이를 실제 토큰, 공통 UI, 전역 내비게이션으로 옮긴다. D3에는 개인 페이지, 커뮤니티·모임, 채팅·DM, 메타버스 배경 시안을 전달한다.

## 구현 작업

- [ ] 색상(라이트 기준), 텍스트·배경·경계·상태 색상, 타이포 스케일, 간격, 모서리, 그림자 토큰을 `app/globals.css`의 CSS 변수와 Tailwind 4 테마에 정의한다. 다크 모드는 후속 범위다.
- [ ] 360px 모바일부터 1440px 데스크톱까지 대응한다. 768px 미만은 모바일, 이상은 데스크톱 전환점으로 사용한다.
- [ ] `components/ui/`에 Button, Input, Textarea, Card, Tabs, Modal/모바일 BottomSheet, Toast, EmptyState, ErrorState, Avatar, Skeleton의 기본형을 만든다. 비활성·오류·로딩·키보드 포커스 상태를 포함한다.
- [ ] `components/layout/`의 임시 셸을 교체한다. 모바일에는 하단 탭, 데스크톱에는 사이드바를 두고 현재 위치를 시각적·접근성 속성으로 알린다. `내 기록`(`/me`)과 `마이페이지`(`/mypage`)를 구별한다.
- [ ] 공개 경로(`/`, `/login`, `/signup`, `/guide`, `/terms`, `/privacy`)에서도 화면이 깨지거나 내비게이션이 불필요한 개인정보를 노출하지 않도록 한다.
- [ ] 태일 화면에서 사용할 공통 컴포넌트 사용 예와 토큰 이름을 문서화한다. 상대 소유 화면을 직접 바꿔야 하면 PR에 경로와 이유를 쓴다.
- [ ] 최종 무드보드·와이어프레임·시안 공유 위치를 데일리 로그에 적는다. 글꼴·아이콘·일러스트의 상업 이용 라이선스와 출처를 README에 남긴다.

## 완료·검수 기준

1. 모바일 360px에서 주요 내비게이션 항목을 조작할 수 있고, 데스크톱 1440px에서 사이드바가 안정적으로 보인다. 가로 넘침과 콘텐츠 가림이 없다.
2. 공통 컴포넌트의 기본·로딩·오류·비활성 상태가 서로 일관되고 키보드 포커스가 보인다. 모달·BottomSheet에는 열기, 닫기, 포커스 이동이 가능하다.
3. 대시보드와 로그인 화면을 공통 토큰만으로 표현할 수 있다. 태일이 D3 화면 작업에 공통 컴포넌트를 가져다 쓸 수 있다.
4. `npm run lint`, `npm run typecheck`, `npm run build`가 통과하고 PR 프리뷰에서 모바일·데스크톱을 확인한다.

## 의존성·전달

D1 디자인 방향과 대시보드 와이어는 태일의 D2 타이머 UI 입력이다. 기본 UI는 D2 종료까지 PR로 전달한다. 커뮤니티·메타버스 시안은 D3 종료까지 공유한다. 기존 Next.js 16 규칙을 확인하고 코드 작업 전에 `node_modules/next/dist/docs/`의 관련 문서를 읽는다.
