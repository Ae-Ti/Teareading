# 랜딩·약관·개인정보처리방침 작업 명세

- 담당: 웅싯 / 일정: D6 / 우선순위: 랜딩 P1, 약관·개인정보 문서 출시 전 필수
- 작업 브랜치: `feat/woong-landing-legal`
- 대상: `/`, `/terms`, `/privacy`, 가입 화면의 안내 링크
- 기준: 1주 개발 계획 3.2·4.1·6.4·출시 체크리스트

## 이용자 흐름

비로그인 이용자는 랜딩에서 서비스 목적과 주요 기능을 이해하고 회원가입 또는 로그인으로 이동한다. 로그인 이용자가 `/`로 들어오면 `/dashboard`로 이동한다. 약관과 개인정보처리방침은 로그인 없이 읽을 수 있으며 가입 화면에서 접근 가능하다.

## 구현 작업

- [x] `/`에 다도·독서 타이머, 기록, 모임·교류를 간결하게 소개하고 가입·로그인 진입점을 둔다. 실제 출시 범위에 없는 기능을 제공 중인 것처럼 표현하지 않는다.
- [x] 로그인 상태에 따라 `/dashboard`로 이동하는 흐름을 만들고, 로그인 상태 확인 중 깜박임이나 반복 이동이 생기지 않게 한다.
- [x] `/terms`에 서비스 이용 조건 초안을, `/privacy`에 실제 수집·이용 항목과 처리 방식을 정리한다. 최소 수집 항목은 이메일, 닉네임, 프로필 이미지, 작성 콘텐츠, 활동 기록이다.
- [ ] ⏳ (운영 정보 대기 — `lib/legal.ts`) 개인정보 문서에는 처리 목적, 보관·삭제 기준, 제3자 서비스 사용, 이용자 문의 창구 등 실제 운영 정보를 확인해 채운다. 운영 주체·연락처 등 확인되지 않은 값을 임의로 확정하지 않는다.
- [x] 가입 화면에서 약관·개인정보처리방침으로 이동할 수 있게 하고 개인정보 수집·이용 동의와 만 14세 미만 가입 제한 안내를 연결한다. 링크에서 돌아와도 입력 흐름이 이어지게 한다.
- [x] 두 공개 문서의 제목, 시행일 또는 개정일, 읽기 쉬운 본문 구조와 모바일 타이포그래피를 갖춘다. 링크가 전역 내비게이션·푸터에서 접근 가능한지 확인한다.

## 완료·검수 기준

1. 비로그인 `/`에서 가입·로그인으로 이동하고 두 문서를 읽을 수 있다. 로그인 상태의 `/`는 대시보드로 이동한다.
2. 가입 화면의 문서 링크와 동의 안내가 동작한다. 공개 문서는 로그인 요구 없이 직접 URL로 접근할 수 있다.
3. 360px과 1440px에서 본문을 읽을 수 있고 가로 넘침이 없다. 잘못된 링크·빈 문구·임시 플레이스홀더가 없다.
4. 문서 내용이 실제 데이터 수집·Storage·분석 이벤트 사용과 맞는지 출시 전에 확인한다. `npm run lint`, `npm run typecheck`, `npm run build`와 프리뷰 확인을 마친다.

## 의존성·PR 경계

로그인 판별은 인증 기능과 공통 레이아웃을 사용한다. 개인정보·약관의 운영 주체와 연락처 등 실제 값은 서비스 운영자가 확정해야 게시 문구가 완성된다. 랜딩은 P1이지만 공개 문서 게시와 가입 동의 안내는 출시 전 확인 항목이다.
