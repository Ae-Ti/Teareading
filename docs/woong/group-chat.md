# 모임 단체 채팅 작업 명세

- 담당: 웅싯 / 일정: D4 / 우선순위: P0
- 작업 브랜치: `feat/woong-group-chat`
- 대상: `/groups/[id]/chat`, `group_messages`
- 기준: 기능명세 6.2, 1주 개발 계획 3.3·4.1·5.3

## 이용자 흐름

모임에 가입한 이용자가 모임 상세에서 채팅방으로 이동해 최근 메시지를 읽고 전송한다. 전송 중·성공·실패 상태를 구별하고 실패한 메시지를 다시 보낼 수 있다. 비회원은 채팅 내용에 접근할 수 없고 가입 안내를 본다.

## 구현 작업

- [x] `group_messages` 테이블을 새 마이그레이션으로 추가한다. 필수 컬럼은 `id`, `group_id`, `sender_id`, `body`, `client_id` unique, `created_at`이다. 본문 길이와 빈 문자열 처리 규칙을 서버/DB에서 검증한다.
- [x] RLS로 해당 모임 멤버만 조회·전송할 수 있게 한다. 탈퇴 후 새 메시지 조회·전송도 차단한다. `group_id`, `sender_id`는 클라이언트 값을 그대로 신뢰하지 않는다.
- [x] 채팅 화면에 최근 50개 메시지를 시간순으로 표시하고, 위로 스크롤하면 이전 메시지를 추가로 가져온다. 내 메시지·상대 메시지, 빈 상태, 로딩, 조회 실패를 구분한다.
- [x] 전송 시 클라이언트 UUID `client_id`를 한 번 만들고 낙관적으로 표시한다. 네트워크 실패 후 재시도할 때 **같은** `client_id`를 사용하며 DB unique 제약으로 중복 저장을 막는다.
- [x] Supabase Realtime Postgres Changes로 새 메시지를 수신하고 목록 조회 결과와 중복되지 않게 합친다. 페이지 이탈·모임 전환 시 구독을 해제한다.
- [x] 메시지 전송이 실제 저장된 뒤 `group_message_sent` 이벤트를 기록한다. 실패한 시도는 성공 이벤트로 세지 않는다.
- [x] 태일의 `groups`·`group_members` 마이그레이션이 아직 머지되지 않았다면 시드/목 데이터로 UI를 먼저 구현하고, 통합 전 최신 `main` 스키마와 타입을 반영한다.

## 완료·검수 기준

1. 두 계정이 같은 모임에서 주고받은 메시지를 새로고침 없이 수신하고 재진입 시 같은 기록을 본다. 위로 스크롤하면 이전 메시지가 중복 없이 붙는다.
2. 네트워크를 끊고 전송하면 실패 상태와 재시도 버튼이 나온다. 재시도·빠른 중복 클릭 후 DB에는 `client_id`당 메시지 1건만 남는다.
3. 비회원·탈퇴 회원은 URL 직접 접근 및 DB 조회·전송이 거부된다. UI 안내와 RLS 결과를 모두 확인한다.
4. 모바일 360px과 데스크톱 1440px에서 입력창과 메시지 목록을 조작할 수 있다. 이벤트와 `npm run lint`, `npm run typecheck`, `npm run build`를 확인한다.

## 의존성·PR 경계

태일의 모임 스키마가 선행 조건이다. 채팅 UI는 공통 디자인 시스템을 사용한다. 마이그레이션과 RLS가 포함되므로 태일 확인 후 머지하고 `types/database.ts`를 같은 PR에서 재생성한다. 이미 머지된 마이그레이션은 수정하지 않는다.
