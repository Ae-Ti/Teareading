# 랜딩·약관·개인정보처리방침 작업 기록 — 2026-11-08

브랜치: `feat/woong-landing-legal` (`main` 기준. 마이그레이션 없음 → 다른 PR과 독립적으로 머지 가능)

## 구현

- `/` 랜딩: 소개, 타이머 미리보기 그림, 기능 4개(타이머·기록장·찻집·모임과 메시지 — 실제 출시 범위만), 3단계 사용법, 가이드 3편(로그인 없이 읽기), 가입·로그인 진입.
- 로그인 상태로 `/`에 오면 **proxy에서** `/dashboard`로 보낸다. 화면이 그려지기 전에 서버에서 이동하므로 깜박임·반복 이동이 없다. (`lib/supabase/proxy.ts`는 태일 소유 파일 — 교차 수정)
- `/terms`, `/privacy`: 로그인 없이 열람, 시행일, 목차(앵커), 표는 좁은 화면에서 표 안에서만 가로 스크롤.
- 전역 푸터: 가이드·이용약관·개인정보처리방침. 채팅·DM처럼 화면을 꽉 채우는 화면에서는 숨긴다.
- 가입 화면의 문서 링크는 기존대로 새 창이라 돌아와도 입력이 유지된다(E2E로 확인).

## 개인정보처리방침 — 실제 구현과 맞춘 내용

| 항목 | 근거 |
|---|---|
| 필수: 이메일·비밀번호·닉네임 / 선택: 프로필 이미지·소개 | 가입 폼, `profiles` |
| 작성 콘텐츠: 독서기록·차 칼럼·모임 이름/소개·단체 채팅·DM | 각 테이블 |
| 활동 기록: 타이머·출석·모임 가입·차단·찻집 입퇴장·캐릭터·이용 이벤트(기기 구분) | `timer_sessions`, `group_members`, `blocks`, `space_visits`, `space_avatars`, `events` |
| 공개 범위: 공개 프로필 항목, 찻집 Presence, 프로필 이미지는 URL로 공개 | `/u/[id]`, 공개 버킷 |
| 탈퇴 시 삭제, 이벤트는 연결 끊긴 통계로만 남음 | 모든 FK `on delete cascade`, `events.user_id`만 `set null` (로컬 DB에서 확인) |
| 위탁·국외 이전: Supabase, Vercel | 인프라 |
| 쿠키: 로그인 유지용만 | 광고·분석 쿠키 없음 (Vercel Web Analytics를 켜면 문서 수정 필요) |

## ⚠️ 출시 전 운영자가 채울 값 (`lib/legal.ts`)

`operator`(운영 주체), `privacyOfficer`(개인정보 보호책임자), `contactEmail`(문의·탈퇴 요청 메일), `dataRegion`(Supabase 프로덕션 리전).
비어 있으면 화면에 "출시 전 공지 예정"으로 보이고 `npm run test:legal`이 실패한다. 값을 넣고 `test:legal`이 통과해야 Go/No-go의 "약관·개인정보처리방침 게시"를 체크한다.

## 운영 절차: 계정 정지·탈퇴 처리 (개발계획 6.4-3)

이용자는 **마이페이지 → 회원 탈퇴**에서 직접 탈퇴할 수 있다(프로필 이미지 파일 삭제 → 계정 삭제 순서로 자동 처리, `lib/account.ts`). 아래는 문의 메일로 요청이 오거나 운영자가 직접 정지·삭제해야 할 때의 절차다.

1. 요청 메일 주소가 가입 이메일과 같은지 확인한다.
2. Supabase 대시보드 → Storage → `avatars` 버킷에서 `{user_id}/` 폴더의 파일을 **반드시 먼저** 삭제한다. Storage는 회원 삭제와 연결돼 있지 않아 자동으로 지워지지 않고, 지우지 않으면 공개 URL로 계속 보인다 (개인정보처리방침에 "프로필 이미지 파일도 삭제"로 고지함).
3. Authentication → Users에서 해당 사용자를 삭제한다. 프로필·기록·메시지·모임(모임장인 모임 포함)·차단·찻집 기록이 함께 삭제되고, `events`는 `user_id`가 비워진다.
4. 처리 결과를 요청자에게 회신한다.

일시 정지만 필요하면 Authentication → Users → 해당 사용자 → **Ban user**(기간 지정)를 쓴다. 로그인과 세션 갱신이 막힌다.
