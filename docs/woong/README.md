# 웅싯 담당 작업 명세

기준: [1주 개발 계획](../티어리딩_1주_개발계획_2026-11-02.md)과 [기능명세서](../###%20서브%20프로젝트%20-%20다도%20독서%20타이머%20메타버스%20플랫폼%20(티어리딩%20teareading)_기능명세서_2026-10-29.md). 이 문서는 구현 범위와 검수 기준을 정리한 작업 명세이며, 체크박스는 구현 완료 여부를 뜻한다. 문서 커밋만으로 완료 처리하지 않는다.

## 담당 범위와 작업 순서

| 순서 | 기능 | 우선순위 | 작업 브랜치 | 산출물 |
| --- | --- | --- | --- | --- |
| D1~D2 | 디자인 시스템과 전역 내비게이션 | P0 기반 | `feat/woong-design-system` | 토큰, 공통 UI, 모바일·데스크톱 셸, 화면 시안 |
| D2 | 회원가입·로그인·로그아웃·세션 보호 | P0 | `feat/woong-auth` | 인증 화면, 보호 경로, 복귀 URL |
| D3 | 마이페이지·프로필 수정·공개 프로필 | P0 | `feat/woong-profile` | 프로필 화면, 아바타 업로드 |
| D4 | 모임 단체 채팅 | P0 | `feat/woong-group-chat` | 실시간 메시지, 전송 상태와 재시도 |
| D5 | DM 및 차단 | DM P0, 차단 P1 | `feat/woong-dm` | 대화 목록·화면, 차단 정책 |
| D6 | 랜딩·약관·개인정보처리방침 | 랜딩 P1, 출시 문서 | `feat/woong-landing-legal` | 비로그인 진입, 공개 문서 |

각 기능 브랜치의 상세 명세는 해당 브랜치의 `docs/woong/` 파일에 둔다. 브랜치는 모두 같은 `origin/main`에서 시작하며, 명세 커밋에 구현 코드는 포함하지 않는다. 기능 구현 시에는 해당 브랜치에서 작업하고, 최신 `main`을 반영한 뒤 PR을 연다.

## 공유 영역과 의존성

- 웅싯 소유: `components/ui/`, 전역 레이아웃·내비게이션, `app/globals.css`, 인증·프로필·메시징 관련 화면.
- 태일 소유: `lib/supabase/`, `lib/track.ts`, 타이머·기록·모임·가이드·메타버스 기능. 인증 경로 보호로 `lib/supabase/proxy.ts`를 수정하면 PR에서 교차 수정 사실을 명시한다.
- `profiles`와 `events`는 첫 마이그레이션에 있다. 모임 채팅은 태일의 `groups`·`group_members` 마이그레이션이 필요하다. 그 전에는 시드 데이터나 목으로 UI를 진행한다.
- DB 변경은 `supabase/migrations/`에 새 타임스탬프 파일로만 추가한다. 이미 머지한 파일은 수정하지 않는다. 테이블에는 RLS 정책을 붙이고 `types/database.ts`를 생성 명령으로 갱신한다. 인증·RLS·마이그레이션 PR은 태일 확인 후 머지한다.
- `/me`는 태일 담당 개인 기록장, `/mypage`는 웅싯 담당 계정·프로필 화면이다. 명칭과 접근 권한을 혼동하지 않는다.

## 공통 완료 기준

- 기능별 정상 흐름, 빈 상태, 로딩, 실패·재시도, 권한 없음 상태를 화면에서 확인한다.
- 360px 모바일과 1440px 데스크톱에서 핵심 흐름을 완료하고 키보드로 주요 조작을 할 수 있다.
- 다른 계정으로 본인 전용 데이터 접근을 시도해 서버/DB 권한 정책을 확인한다. UI에서 숨기는 것만으로 권한을 대신하지 않는다.
- 해당 기능의 `lib/track.ts` 이벤트가 성공 시에만 기록되는지 확인한다.
- PR 설명에는 변경 범위, 의존성, 확인 방법, 가능하다면 프리뷰 URL을 적는다. `npm run lint`, `npm run typecheck`, `npm run build`를 통과시킨다.
- 상대의 마지막 데일리 로그를 읽고 필요한 의존성 변경을 확인한다. D3 핵심 흐름 통합, D6 반응형·교차 테스트, D7 출시 점검에 참여한다.

## Git 작업 원칙

`main`에 직접 커밋·푸시하지 않는다. `feat/woong-<기능>`에서 작고 검토 가능한 PR을 만든다. 병렬 브랜치 간 공통 파일을 변경할 때는 먼저 합쳐진 PR의 최신 `main`을 각 브랜치에 반영한다. 마이그레이션·RLS·인증 변경은 대기 시간과 관계없이 상대의 확인을 받고 머지한다.
